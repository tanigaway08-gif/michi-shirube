# 未知しるべ
---

## 1. サービス概要

このサービスは、『①日程 ②予算 ③現在地 ④交通手段 ⑤誰と行くか』の条件から最適な旅行先を3つ提案し、ボタン1つでサクッと簡単に『旅のしおり』を自動作成することができるサービスです。旅行という大切なイベントを家族や友人と一緒に**計画段階から楽しめる**ようになります。

「家族や友人と旅行に行きたいけれど、計画を立てるのが苦手・面倒」という方の**心理的負担をなくし**、隙間時間でサクッと計画を完成させられる**気軽さ**を提供します。また、「計画は好きだけれど、行き先がいつもマンネリ化してしまう」という方に対しても、自分にはない新しい視点から提案を行うことで、**未知の場所への切符を手にするワクワク感**を届けます。

---

## 2. このアイデアはどこから生まれたか

### 2-1. きっかけとなった体験・感情
私は旅行の計画を立てること自体が好きで、休日に家族と出かける際も楽しみながら計画しています。しかし、予算や移動範囲を考慮して自力でリサーチをしていると、どうしても行き先がマンネリ化してしまい、「自分の知らない素敵な場所がもっとあるはずなのに、見つけきれない」という歯痒さを感じていました。一方で、職場の同僚と話した際、「旅行は好きだけど、計画を立てるのは面倒だから嫌い」という全く別の視点の意見を聞きました。これらの経験から、どんな人でも気軽に旅行計画を作れるアプリがあれば、同僚のように「計画が煩わしい人」のハードルを下げるだけでなく、私のように「計画が好きな人」にとっても、自分では思いつかないような新しい場所や情報と出会える「ワクワク感」を提供できると考えました。計画の苦痛をなくし、さらに未知の情報に出会える喜びをプラスすることで、誰もが旅行をより一層楽しめるアプリを作りたいです。


### 2-2. なぜそれが「気になった」のか

私は元々、自由で楽しいことを好む性格で、新しい学びや未知の体験に触れることが大好きです。私にとって「自由である」ことは、「多くの選択肢を持っていること」と同義です。そのため、自分にはない視点や価値観を取り入れて旅行計画が立てられれば、まだ見ぬ世界を知る素晴らしいきっかけになると直感しました。それに加えて、私は「周りの人が喜ぶ姿を見ること」に何よりの喜びを感じます。世の中には、家族や友人を旅行で喜ばせるために、忙しい日常の合間を縫って一生懸命に情報収集をしている方がたくさんいます。そうした方々がもっと気軽に、ワクワクしながら計画を立てられるようになれば、旅行という体験がより豊かなものになり、結果として笑顔になる人が増えるのではないか。そんな思いが、このアプリを作りたいという強い動機になっています。

## 3. 課題の整理

### 3-1. 表に見えている困りごと

その体験の中で、私が最初に感じた困りごとは「自力での情報収集の限界による、行き先のマンネリ化」です。私は元々旅行計画を立てるのが好きですが、予算や時間などの条件内でリサーチをしていると、どうしても行き先が定番の場所に偏ってしまい、「せっかく旅行に行くのに代わり映えしない」というジレンマを感じていました。さらに、職場の同僚と話をしているうちに、「そもそも計画を立てること自体が難しくて煩わしいから嫌い」という人が多いことにも気づきました。この煩わしさのせいで、不完全な計画のまま当日を迎えてしまう人もいます。つまり、最初に感じた「マンネリ化」を深掘りしていく中で、根本には「旅行計画にかかる労力と手間の大きさ」という共通の困りごとがあることに気づき、これを解決すべきだと考えました。


### 3-2. 本当に解決したい課題は何か

- なぜ？
予算や移動時間など、考慮すべき条件が多くて情報収集や調整に時間がかかり、疲れてしまうからです。

- なぜ？
計画段階で疲れてしまうことにより、不完全な計画のまま旅行の当日を迎えてしまったり、楽しいはずの旅行を煩わしいものと感じてしまうからです。

- なぜ？
不完全な旅行計画や心から楽しめていない状態が顔や態度に出てしまうことで、同行者である家族や友人と揉める原因となってしまうからです。

→ **本当に解決したい課題**

計画に伴う過度な心理的負担と、旅行の空気を壊してしまうことへの不安

## 4. 想定ユーザーについて

### 4-1. 想定しているユーザー
  
  - **年齢 30代:** 子供が成長して家族で旅行に行く機会が増えたり、旅行に行き慣れて行き先がマンネリ化してくる年代であるため
  
  - **生活・状況：** 平日は仕事、休日は家事育児で忙しく計画を練る時間がない：日々の忙しさのせいで時間がかかる計画を立てるという作業を煩わしく感じてしまうため。アプリを使うことで、時間短縮や心理的負担を大幅に減らすことができ、さらに計画を立てること自体を家族や友人と一緒に楽しむことができるようになる。

  - **環境：** まとまった時間が取れず、通勤中の電車内や、子供を寝かしつけた後のベッドの上など、スマホ片手での隙間時間に調べ物をしている。：PCを使って複数のサイトを見比べたり、情報をまとめる時間が取れないため。スマートフォンでもサクッと候補が表示されるようにUIを整え、簡単なボタン操作によって情報をまとめる機能を実装する。
  

### 4-2. 自分とユーザーの距離

職場の同僚：実際に職場の同僚から「家族と旅行に行く予定だが、予算や時間を考慮して一から計画を立てるのは苦手だし、煩わしくて疲れてしまう」というリアルな悩みを聞いたため。実在する特定の個人の課題を起点にしている。

### 4-3. 実際に使われる可能性について(需要・存在確認)

- **最初に使ってくれそうな人：** ヒアリングを行った職場の同僚（30代・子育て世代）

- **どんな場面で思い出すか：** 週末や連休に向けて「どこに行こうか？」と家族で話し合い、具体的な行き先やスケジュールを決めなければならない時

- **今、代わりに使っているもの：** nstagramやTikTokなどのSNS、旅行系Webメディア、Googleマップ

- **それでも置き換える理由：** SNS等で「行きたい場所」は見つけられても、結局そこから「予算、移動時間、移動手段などを調べてスケジュールを組む」という煩わしい作業が発生します。本アプリを使えば、情報収集から現実的な行程への落とし込みまでを簡単な操作で実行でき、計画にかかる大幅な時間短縮と心理的負担の軽減を実現できるというメリットがあります。

## 4-4. ユーザーがサービスを導入して利用するまでのイメージ(導入・継続の流れ)

- **きっかけ：** 週末のお出かけや長期休暇で、家族・友人と「どこに行こうか？」と話し合っている場面。いざ行き先を調べようとした時に、「予算や時間を考慮して条件に合うものを探すのがしんどい」「いつも同じような場所でマンネリ化している」と、計画の煩わしさを感じたタイミングで利用を思い出す。

- **最初の一歩：** 最初のハードルを下げるため、「予算や場所などの条件を入力して候補を出す」「旅のしおりを作成して共有する」というコア機能はユーザー登録不要ですぐに体験できるようにする。その上で、旅のしおりを手動で編集できる機能、旅行後にアルバムを作る機能、都道府県制覇マップ機能を利用するタイミングで、自然な流れでユーザー登録を促す。

- **続ける理由：** 本アプリを使うことで「面倒な情報収集から解放され、同行者と揉めることなく旅行が成功した」という安心感と成功体験が得られるため。また、作成した「旅のしおり」が蓄積されることで、過去のお出かけのログ（思い出）として機能し、「次のお出かけもこのアプリでサクッと決めよう」という習慣化に繋がるため。

### 5-2. それでも自分が作りたい理由

既存の旅行系サービスはどれも「旅行の計画が好きな人」を前提に作られており、計画が苦手な人に対する助けになっていないことに強い違和感がありました。このサービスでは、目的地すら決まっていない状態から、たった5つの条件を入力するだけで旅行先の選択肢を出せる気軽さにあります。また、旅のしおりを作成するサービスも、すでに完成した旅程を綺麗に整えるためのツールであり、ゼロから計画を立てるのが苦痛な方にとっては非常に使いにくいのが現状です。つまり、**「計画すること自体のハードル」を下げるサービス**が存在しないため、そこを解決できるアプリを自分自身の手で作りたいと考えました。

### 5-3. 差別化ポイント

このアプリは、「旅行に行きたいけれど計画が面倒な人」が、休日に「どこか行きたいな」と思い立ったその瞬間に、スマホ一つでサクッと旅程を完成させられる『気軽さ』を提供できます。何時間もリサーチする心理的負担をゼロにするだけでなく、旅行先のマンネリ化を防ぎ、自分では思いつかなかった新しい場所へ行く『ワクワク感』を得ることができます。

## 7. このアプリで実現すること

### MVPで作る機能（ログイン不要で「サクッと計画〜共有」まで完結）
- **旅行条件入力機能（日程、予算、出発地、交通手段、誰と行くか）**
  - 最小限の5項目だけで、迷わず直感的に入力できるフォーム、旅行先はエリアではなく施設を提案
- **旅行は日帰りを想定**
  - まずは日帰り旅行のみすることで実装の難易度を易しくする
- **現在地から出発地を簡単に選択できる機能**
  - 文字入力の手間すら省き、ワンタップで出発地を設定可能に
- **AIによって旅行先を3つ提案する機能**
  - 情報過多にならない「3つ」に絞り、定番から穴場まで未知の行き先を提案
- **ボタン1つで「旅のしおり」を作成する機能**
  - 気に入った提案を選ぶだけで、タイムスケジュール入りのしおりを自動生成
- **URL発行による「旅のしおり」共有機能**
  - 発行されたURLをLINE等で送るだけで、同行者とすぐに計画を共有可能

### 本リリースで作る機能（ログイン機能により「高度な条件での提案と思い出の蓄積」を実現）
- **宿泊つきの旅行計画を実装**
- **ログイン・ログアウト機能**（※以下の機能はログインユーザー限定）
- **こだわり条件の追加機能（ペット同伴可、雨天でも楽しめる 等）**
  - 自力でのリサーチが特に大変な条件を追加し、より個別の事情に寄り添った提案を実現
- **旅のしおりを自分の好きなようにカスタマイズできる機能**
  - 生成されたしおりを自分好みに修正できる
- **旅行アルバム機能**
  - 生成したしおりと紐づけて、旅行後の写真や思い出を記録・振り返りできる機能
- **都道府県制覇マップ機能**
  - 訪れた場所が可視化され、「次はまだ行ったことのない県へ行こう」と未知の場所へのモチベーションを高める機能

## 8. このアプリの懸念点とその対策

### 懸念点①　AIが提案した3つの旅行先がすべてユーザーの好みに合わず、「結局使えない」と判断されて離脱されてしまう可能性

- **理由：** 一般的な旅行計画は「ここに行きたい」という目的地ありきで始まりますが、本アプリは「日程・予算・出発地」などの条件から逆算して未知の場所を提案する仕組みです。そのため、ユーザーの潜在的な好みを外してしまい、「どこにも行きたくない」と感じさせてしまうリスクがあります。

- **対策：** 3つの提案が似たような場所にならないよう、AIへのプロンプトで「①王道・人気スポット」「②自然・癒やし系」「③グルメ・体験重視」のように異なるジャンルの切り口で3案を出力するよう制御します。これにより、どれか1つはユーザーの気分に刺さる確率を高めます。もし3つともピンと来なかった場合でも、条件を入力し直すことなく「別の3案を見る」ボタン1つで手軽に再提案を受けられるUIにし、心理的負担を増やさずに別案を探せるようにします。ログイン機能実装後は、「旅の気分の選択（例：のんびり、アクティブ）」や「過去のしおり作成履歴・都道府県制覇マップのデータ」をAIのプロンプトに組み込み、使えば使うほど好みに合った提案ができるように改善します。

### 懸念点②　AIが実在しない観光地を提案したり、物理的に移動不可能なタイムスケジュール（しおり）を作ってしまう。

- **理由：** 生成AIの特性上、もっともらしい嘘（ハルシネーション）をつく可能性があり、「不完全な計画のまま当日を迎えて困る」という本来の課題解決に逆行してしまうため。

- **対策：** プロンプトで「実在する有名な施設・駅名のみを使用すること」を厳密に指示する。また、予算や移動時間の厳密な計算をAIに丸投げするのではなく、AIには「条件に合いそうな大まかなエリアやスポットの選定」と「しおりのタイムラインの枠組み」だけを作らせ、実際の移動時間や経路は『Google Maps API』に裏付け計算させる

## 9. 今後の展開・発展の方向性

### 観点

- **使い続ける理由：** 『旅行』は多くの人が定期的に行うイベントであることから、このアプリを使って未知の旅行先に出会えるワクワク感を味わうことができれば、次もこのアプリを使おうという気持ちになる。また、計画の心理的負担を減らすことに成功すれば、忙しい中で家族のために旅行先のプランニングをしている家庭にとっての大きな助けとなり、継続して使い続ける理由となる。

- **使い続けることで変わること：** 旅行のアルバムや都道府県制覇マップを更新して、自分や家族、友人との思い出をストックすることができ、さらにその履歴を計画の条件として加えることで、より自分好みの旅行先と出会えるようになる。

- **他の人と関わる余地：** 条件を入力して提案された旅行先を見る段階で、家族や友人と一緒に楽しむことができる。さらに、しおり生成後にURLを発行することで、内容を家族や友人と共有することができる。

- **運用・仕組みでの価値：** 「都道府県制覇マップ」や「こんな未知の旅行先が提案された！」という結果を、ボタン1つでX（旧Twitter）に画像付きでシェアできるようにし、周りの人と盛り上がれる仕組みを作る。

### 今考えている発展案

- **機能追加の方向性：** ユーザー向けにアンケートを実施したり、FBをいただいて計画の条件を追加する。また旅行のアルバム作成や都道府県制覇マップを実装して、旅行後の楽しみもこのアプリで使えるように機能追加する。

- **UI・体験の改善：** 家族や友人と一緒に楽しめるようにシンプルかつ見やすいUIとする。検索やしおり作成はボタン１つで簡単に実行できるよう整備し、導線をわかりやすくする。

- **機能以外の工夫：** SNS（Xなど）や技術記事での発信において、「旅行アプリ」として広く曖昧に宣伝するのではなく、「旅行は好きだけど計画が面倒な人」「行き先がいつもマンネリ化している人」という具体的な悩みにフォーカスして魅力をアピールする。また、生成された「未知の旅行先」や「都道府県制覇マップ」をSNSでワンタップでシェアできる仕組みを整え、口コミで自然と広がる導線を作る。

## 10. 技術スタック（手段としての技術）

### 10-1. 使用予定の技術

- **バックエンド：** Ruby / Ruby on Rails
- **フロントエンド：** Hotwire (Turbo / Stimulus) / JavaScript
- **CSSフレームワーク：** Tailwind CSS
- **データベース：** PostgreSQL
- **インフラ・デプロイ先：** Render
- **開発環境：** Docker / Git / GitHub

### 使用予定の外部API・ライブラリ（Gem）

**【MVPから導入するもの】**
- **AI提案機能：** OpenAI API
- **位置情報・最寄駅取得：** Google Maps API
- **API通信処理：** `faraday`および`ruby-openai`

**【本リリースで導入予定のもの】**
- **ユーザー認証：** `devise`
- **画像アップロード（アルバム機能用）：** `AWS S3`
- **都道府県制覇マップ描画：** JavaScriptライブラリ

**【本リリース後の技術的検討】**
- フロントエンドの一部コンポーネントにおける React の導入（※本リリース完了後に技術検証を実施）

### 10-2. 技術選定の比較検討

| 技術カテゴリ | 候補 | 採用 / 不採用 | 理由 |
| --- | --- | --- | --- |
| フロントエンド | Hotwire (Turbo / Stimulus) | 採用 | Rails標準の構成を活かしつつ、ReactのようなSPAに近いサクサクとした操作感（画面遷移なしのAI提案表示など）を低コストで実現できるため。 |

### 10-3.キャッチアップ不足の懸念

**OpenAI APIのJSON出力指定（Structured Outputs等）の具体的な実装方法** 

理由： 「ボタン1つで旅のしおりを作成する」という要件を満たすためには、AIから返ってくるテキストをプログラムで扱いやすいJSON形式に固定する必要があります。プロンプトの工夫だけでなく、API側のパラメーター指定や、Rails側での安全なJSONパース（解析）処理について、まだ具体的な実装手順のキャッチアップが不足しているため、これから公式ドキュメント等で検証を進める必要があります。

**外部API通信時のエラーハンドリングとタイムアウト処理** 

理由： OpenAI APIやGoogle Maps APIなど、複数の外部APIを同時に叩く構成になるため、API側のサーバーダウンや応答遅延が発生するリスクがあります。その際、Railsの画面が固まったりアプリがクラッシュしないよう、適切なエラーハンドリングや非同期処理をどう組み込むか、知識が不足しているため学習が必要です。A
